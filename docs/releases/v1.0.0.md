# Spring Architecture Patterns v1.0.0

The first stable release demonstrates a production-minded modular monolith
through one complete return and refund workflow.

## Highlights

- business-aligned Spring Modulith modules with executable dependency rules
- framework-independent domain and application layers enforced by ArchUnit
- PostgreSQL persistence, Flyway migrations, and real Testcontainers coverage
- durable event publication with idempotent consumers and operator recovery
- optimistic locking, an idempotent refund boundary, and a monotonic CQRS view
- OAuth 2.0 scope protection, RFC 9457 errors, health probes, and Prometheus
- layered, non-root OCI packaging with a read-only Compose runtime
- signed HTTP end-to-end verification with temporary test credentials

## Delivery semantics

Cross-module events are delivered at least once. Consumers use database-backed
deduplication or idempotent state transitions instead of claiming exactly-once
delivery. The architecture documentation describes crash, retry, and recovery
behavior explicitly.

## Artifacts

- `spring-architecture-patterns-1.0.0.jar`: executable Java 21 application
- `spring-architecture-patterns-1.0.0.jar.sha256`: checksum for the JAR
- `ghcr.io/wasiliy-strecker/spring-architecture-patterns:1.0.0`: OCI image

The OCI image is also published under the moving `1.0`, `1`, and `latest` tags.
Its registry manifest carries BuildKit provenance and an SBOM.

## Verification

The release commit is checked on Java 21 and Java 25. Separate CI jobs verify
module boundaries, PostgreSQL integration, the secured container workflow, and
CodeQL analysis before the protected branch can be updated.
